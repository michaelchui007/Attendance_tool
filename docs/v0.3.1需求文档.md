## 1. 版本目标

1. 修复 Windows 中文路径导致无法计算、启动时出现控制台窗口的实际使用问题。
2. 支持公司统一调休等未出现在源表申请栏中的人工扣减，并保持计算可追溯。
3. 提供独立系统配置页面，集中管理可自定义的标准工时、正常上下班和午休，并支持不同日期采用不同作息。
4. 一次导入多份月度报表，合并成同一员工的连续统计视图，改善 Windows 等待体验。
5. 在仓库首页提供清楚、稳定的安装包下载入口。

## 3. 统一口径

### 3.1 扣减金额的正负号

用户所说“调休扣减设置为 −8”，应表达为“从余额扣除 8 小时”，不能将内部扣减量设为负数后再做减法。

- 内部实际调休扣减量 D 使用非负分钟，扣 8 小时即 D = 480。
- 页面编辑使用“扣减调休（小时）”，输入 `8`，旁边明确预览“对净剩加班的影响：−8 小时”。
- 为兼容用户习惯，建议输入 `-8` 时明确归一为扣减 8 小时，并立即显示归一结果；不得静默把负扣减解释为增加余额。
- 净剩加班 N = 加班 O − 实际扣减 D；若 O = 0、D = 480，N = −480。
- 未输入/选择自动表示恢复算法；手动输入 0 表示明确不扣，两者不能混淆。

### 3.2 已有规则继续保留

- 04:00 为考勤日边界，次日 04:00 前属于前一考勤日；作息设置不改变此边界。
- 地点福利已取消，不增加恢复开关。
- 实际有效工时以真实打卡跨度扣除适用午休计算，不因正常上下班配置而裁剪到班次窗口。
- 标准工时 S 是独立配置项，默认 480 分钟；仅用户修改标准工时设置时变化，不由上下班和午休净时长自动替代。
- 国家调休日历优先于普通星期规则；公司统一调休由人工记录体现，不擅自修改国家节假日数据。
- 缺卡工时仍为未知。人工扣减不能把未知工时改成零，也不伪造原始请假或打卡记录。
- 未知扣减不当作零；界面、明细、汇总、导出必须使用同一结果。

## 4. 功能需求

### R01：每日手动调休扣减

**明确诉求：** 在编辑入口中可直接处理 11 月 2 日、3 日等公司统一安排的调休，即使报表没有调休申请，也能分别扣除 8 小时。

**用户操作与结果：**

1. “编辑时间”建议调整为“编辑考勤”，其中分开显示打卡时间和调休扣减。
2. 调休扣减提供“自动计算”和“手动指定”两种模式；切换手动后填写小时数，支持分钟精度。
3. 可只修改扣减，原始打卡缺失或时间异常时仍可保存这项修改。
4. 提供修订说明，建议手动扣减时必填，例如“公司统一安排调休”；原自动结果和新结果并列显示。
5. 保存并重算后更新当天、区间及导出；保留“手动扣减”标记。
6. 支持恢复自动扣减；恢复扣减与恢复打卡时间分开操作，避免误删另一项修订。

**规则建议：**

- 手动值是当日最终扣减的覆盖值，不是在自动结果上再加一次。自动扣 3 小时、手动指定 8 小时后，最终 D = 8 小时，不是 11 小时。
- 手动扣减优先于自动封顶规则；否则无打卡、无申请等场景仍无法处理。原始申请量、自动建议扣减和最终实际扣减分别保留。
- 手动值确定后，可以计算该日净额；原始申请解析异常和缺卡提示仍保留，不因已手动处理而删除来源问题。
- 建议范围为 0～24 小时/日、精度 1 分钟，超过当前配置的标准工时需明显提示但允许用户明确应用；是否改为不超过所配标准工时见 D01。
- 批量导入或调整午休后，同一员工同一天的已生效人工扣减继续保留，明确说明未被自动算法覆盖。
- 原始文件不修改；导出记录自动值、手动值、最终值、原因及修订标记。

**用户示例：** 2026-11-02 和 2026-11-03 均无完整打卡、无源申请。分别手动扣 8 小时后，每日净额贡献为 −8 小时，两日共 −16 小时；实际工时仍显示未计算。原始缺卡状态不被伪装成正常出勤。

### R02：按单日和日期段配置午休

**明确诉求：** 除统一午休设置外，支持指定某一天或某一日期段的午休起止时间，方便长周期内作息变化。

建议系统配置中的“作息规则”提供：

- 默认规则：未被其他规则覆盖的日期使用。
- 日期段规则：含开始日期和结束日期，两端均包含。
- 单日覆盖：在日期详情内设置，也可在规则列表查看。

规则优先级为 **单日覆盖 > 日期段规则 > 默认规则**。同级日期段不允许重叠：保存前列出冲突区间并要求调整，不能按最后点击顺序默默覆盖。单日覆盖可落在日期段内，这是显式例外。

每个日期展示最终生效的午休和规则来源。支持编辑、删除规则，删除后回退到下一优先级；保存前预览受影响日期。调整规则后标记待重算，不能把旧结果显示成已按新规则计算。

具体计算与校验：

1. 工作日只扣实际打卡区间与当日午休区间的交集，休息日维持不扣午休。
2. 配置必须是有效时间；起止相同不建议用来表达零午休，提供明确“无午休”选项。
3. 本版建议只支持同一自然日的单段午休，多段休息或夜班另行扩展。
4. 日期段规则可跨月、跨年；当前导入范围外的规则保留但显示本次没有受影响日期。
5. 单日午休与 R03 的上下班时间组成完整作息；校验通过后一起生效，不能使请假分摊和工时扣除采用不同作息。
6. 导出记录每天生效的时段与规则来源，历史结果不会因之后修改默认规则而变化。

### R03：独立配置标准工时与正常上下班时间

**明确诉求：** 提供正常上班、正常下班的设置；标准工时默认每天 8 小时，用户可在系统配置页面独立修改。

正常上下班和午休共同组成“作息方案”，标准工时作为独立字段。默认仍为上班 09:00、下班 18:30、午休 12:00～13:30、标准工时 8 小时。页面分别显示“作息净时长”和“标准工时”，说明两者用途。

上下班和午休可作为默认方案，或绑定 R02 的日期段/单日规则。只修改午休时，保留用户设置的上下班和标准工时；只修改标准工时也不自动平移上下班或午休。标准工时本版建议先作为本次整个统计区间的系统级参数，不额外增加按单日/日期段覆盖标准工时的能力。

**计算口径（标准工时的独立性已由 D02 确认）：**

- 工作日标准工时 S 取系统配置值，默认 480 分钟，可修改为 450 分钟、420 分钟等合法值。内部仍统一使用整数分钟。
- 作息净时长 W = 正常下班 − 正常上班 − 正常时段中的午休。W 仅用于展示和校验作息，不用于替代 S。
- 当日正常工作区间用于分摊请假；当日实际打卡用于计算 E，两者分工不变。
- 普通工作日/国家调休工作日：自动 O = max(E − S, 0)，自动 D = min(L, max(S − E, 0))。
- 休息日标准为 0，完整打卡按原休息日规则计加班；人工扣减按 R01 独立处理。
- 期间应计标准工时按已覆盖工作日逐日累计 S，不能在汇总或导出中仍写死“每天 8 小时”；缺卡工作日仍计入所配标准，未导入区间依 R04 标记不完整。
- W 与 S 不一致时，建议显示差异提示但允许保存，不强制相等、不自动按比例放大或缩小请假量 L。覆盖全天正常工作时段的申请量仍按该时段计算，不能自动补成 S；“全天请假固定扣 S”不属于本轮确认内容。完整打卡扣减仍按上述公式封顶；缺卡保持原有保守处理及待核对提示。

示例：正常作息为 09:00～18:00、午休 12:00～13:30，W = 7.5 小时；标准工时未修改时 S 仍为 8 小时。若当天完整打卡正好覆盖该时段，E = 7.5 小时且无调休，则加班为 0，不自动扣欠工时。只有用户把标准工时明确改为 7 小时并重算后，该日加班才变为 0.5 小时。

校验正常下班晚于上班、午休在正常上下班范围内、净工作时长大于 0。标准工时建议支持大于 0 且不超过 24 小时、精度 1 分钟；空值、非法值或无法精确表示为分钟的输入不能保存。本版建议仅支持同日白班；真实打卡晚于午夜仍按现有 04:00 边界处理，不因班次配置限制而禁止正常跨日下班记录。

### R04：多 Excel 合并导入与连续统计

**明确诉求：** 可一次选择 N 份 Excel，将企业微信分月导出的报表合并为季度等较长期间的统计，不必每月分别运行。企业微信最长导出期间是用户提供的使用背景，本轮未独立核实其平台限制。

**导入交互：**

- 文件选择器支持多选，拖放支持多个 .xlsx；可追加、移除文件，显示文件名、报表期间、状态和重复/冲突提示。
- 不采用“最后选中的文件替换全部已选文件”的隐式行为；替换整个文件集需要明确操作。
- 同一次统计先限定同一员工，沿用个人工具定位；发现不同员工时指出涉及文件并阻止混算，不能仅按显示姓名相同就认定同一人。
- 文件顺序不影响结果，按解析后的日期和打卡时间排序。文件名不作为统计日期依据。
- 一份文件损坏、不可读、缺工作表或员工不一致时，保留列表和其他已解析结果，明确失败文件；用户移除或替换后才能输出完整合计，不静默跳过。

**时间线与去重建议：**

| 情形 | 建议行为 |
|---|---|
| 完全相同文件重复导入，或改名后的相同内容 | 提示重复并只纳入一次，保留可见说明 |
| 同一员工、同一打卡在多份报表重复 | 按完整记录身份去重，不将重复记录变成重复工时；合并来源链接 |
| 相邻月份中同一跨月请假申请重复 | 按申请身份/起止区间去重后逐日分摊，不按文件数重复扣总量 |
| 同一日期有不同但互补的真实打卡，例如一份包含上班、另一份包含下班 | 合并后沿用既有首尾选择规则；正常多次打卡不能仅因时间不同就一律判为冲突 |
| 同一记录的时间/状态矛盾，或同一日完整来源版本、申请版本相互矛盾 | 标为冲突并列出来源；建议用户选择采用的该日来源版本后再计算，不把不同版本中的更早/更晚时间拼成更长工时；缺少足够身份依据时标待核对 |
| 多份报表日期区间相连 | 生成按日期连续的视图，并只计算一次每个日期的标准工时 |
| 文件之间缺少整段日期，例如只有 1 月和 3 月 | 缺口标为“未导入”，不自动当作 2 月每天缺卡或零出勤；总览注明数据不完整 |
| 已导入报表覆盖范围内某天无打卡 | 按已有缺卡/休息日规则处理，与“未导入”分开 |
| 月末打卡在次月 04:00 前 | 合并原始记录后统一按 04:00 归属，跨文件记录不丢失 |

合并顺序应表达为：解析文件和来源 → 确认员工 → 识别重复和冲突 → 合并记录 → 统一日期归属/申请分摊 → 应用作息及人工修订 → 计算及导出。不能将各月已算出的汇总数字直接相加，代替跨文件核对。

**结果及导出：**

- 显示整个已覆盖期间汇总及逐日明细；建议增加按月汇总，用于与原报表核对。
- 全局保留未导入区间和冲突数。完整区间净额只有在相关扣减可确定时才作为确定结果显示。
- 每条记录可追溯来源文件、工作表及行号；查看原记录时能区分同名文件。
- 合并导出生成一个新的结果工作簿，包含总览、分月汇总、每日明细、原始记录、规则/修订及来源清单。源文件不修改。
- 多文件的默认导出目录建议为本次第一个成功加入文件所在目录下的 export_report，页面明确显示并允许修改；时间排序不得暗中改变输出位置。
- 移除文件后重新核对覆盖范围与冲突；对应不到当前数据集的手动修订提示为失效，不自动转移给其他员工或日期。
- N 不预设为 3；大文件/多文件边界依据性能测试公布，不承诺无限文件。

### R05：Windows 读取与重算性能

**明确诉求：** Windows 上读取 Excel 偏慢，批量导入不能进一步放大等待体验。

本轮尚无用户 Windows 设备配置或分阶段计时，不能把慢归因于 Excel 库、编码、杀毒或网络中的某一项。先区分文件选择/校验、引擎启动、解析、日历加载、计算和导出耗时。

建议要求：

1. 选择文件后及时显示已接收状态，处理期间界面保持可操作，不出现无提示的长时间空白。
2. 批量任务显示“正在处理第 X/N 个文件”及阶段；没有实际总量时使用不确定进度，不伪造百分比。
3. 同一文件内容未变化，仅修改打卡、人工扣减或作息时，复用已解析数据；不重复从磁盘加载整个工作簿。
4. 源文件变更、替换或删除时失效缓存并明确提示，不能继续使用旧数据却标成最新。
5. 节假日年度数据在同次任务中复用；网络失败、引擎冷启动和文件解析的等待应分别可定位。
6. 不强制无限并发解析；以稳定内存占用和可解释进度为优先，避免多个大工作簿同时占满内存。
7. 提供取消本次处理的入口；取消后保留上一份成功结果，不能导出半份报告。

**建议的性能验收方法：** 固定同一台 Windows 设备、同一组脱敏样本，区分首次启动和预热后运行；分别测单月、三个月、十二个月文件集，每组至少 5 次，记录中位数及最慢值、各阶段耗时和峰值内存。重算路径应确认不重新解析未变化源文件；用户反馈动作至忙碌提示建议不超过 500ms。整体耗时目标在基线测量后确定，不能在未测量时承诺“秒开”或固定提速百分比。

### R07：Windows 中文路径与文字乱码修复

**现象：** 拖入或浏览选择含中文的 Excel 后，页面出现乱码，计算提示“源文件不存在”。目前需要区分是源文件名/路径已经损坏，还是报表内部中文也发生解码错误。

**目标：** 本地路径和中文内容从 Windows 原生选择/拖放、前端、桌面桥接、Python 引擎到导出全链路无损，不要求用户重命名为英文或修改系统地区设置。

要求覆盖：

1. 中文用户名目录、中文文件夹、中文文件名、空格和括号，以及中英文混合路径；同时验证浏览、拖放、批量多选和自定义输出目录。
2. 不把 Unicode 路径随意按本地代码页重复编码/解码，不靠替换乱码字符“修复”真实路径。
3. 文件不存在和路径传输损坏要可定位；路径不正确时不得回退搜索或打开其他同名文件。
4. Python 打包引擎的输入、输出、错误信息协议都使用明确一致的编码；开发环境通过不能代替冻结程序检查。
5. 姓名、工作表名、申请原文、错误提示及导出文件名正确显示，源文件保持只读。
6. 在中文系统和英文系统中、Windows“使用 Unicode UTF-8 提供全球语言支持”关闭的常见环境下验证；若可用，再覆盖开启环境。
7. 测试必须包含安装后的程序及随包引擎，不仅是 Python 源码或浏览器模拟。

排查方向记录在第 2.2 节；最终修复说明需包含实际复现证据及根因，不将待验证假设写成结论。

### R08：Windows 启动不弹出控制台

**现象：** 安装后启动软件时同步出现命令行窗口。

**目标：** 从桌面快捷方式、开始菜单和应用 EXE 正常启动时只出现主界面；预热、首次计算、后续重算和引擎异常恢复时均不出现额外控制台或黑框闪烁。

建议分别核对主程序的 Windows GUI 子系统配置和后台引擎的创建标志，保留现有标准输入输出通信能力。不能简单关闭计算引擎标准流以隐藏窗口，导致路径传递和计算结果返回失效。

异常在应用中给出提示并保留可诊断日志；主程序退出时正确结束后台引擎。开发调试日志的保留方式不影响正式安装包的无控制台体验。

### R09：独立系统配置页面

**已确认方向：** v0.3.1 提供完整的“系统配置”页面，在考勤工作台保留固定、易发现的入口；无需先导入报表即可进入配置。现有午休折叠区域可以保留摘要或快捷入口，完整设置由配置页面集中管理。

页面建议分为以下区域，不增加与本版无关的主题、权限或服务端设置：

| 区域 | 主要内容 |
|---|---|
| 基础工时 | 每个工作日的标准工时，默认 8 小时；单位、输入校验及恢复默认 |
| 默认作息 | 正常上班、下班、午休起止及无午休选项；并列显示作息净时长与所配标准 |
| 日期规则 | 日期段和单日例外的列表、适用范围、冲突校验、编辑/删除及优先级说明 |
| 导出设置 | 默认输出位置、当前批量文件集的输出位置说明 |
| 规则说明 | 04:00 考勤日边界、休息日处理、人工扣减优先级；取消福利不提供恢复开关 |

**保存与生效建议：**

1. 页面提供“保存配置”“取消修改”“恢复默认”和“返回工作台”。恢复默认先放入草稿，保存后才生效；默认标准为 8 小时，不清除每日人工扣减或打卡修订。
2. 有未保存修改时离开页面提示处理。输入错误定位到字段，保存失败保留草稿和上一份有效配置。
3. 保存前展示主要变化及当前数据受影响范围，特别是标准工时变化和日期段覆盖。无已导入数据时说明将用于后续统计。
4. 保存配置不会悄悄重写已经展示或导出的结果；已有结果标记待重算，可提供“保存并重新统计”以一次完成应用。
5. 每次计算保存完整规则快照，包括 S、每日生效作息和来源。历史导出继续对应其计算时的设置。
6. 系统默认配置建议本地持久化，重新启动后恢复；员工数据修订的存续仍依 D03，不因增加配置页面而自动获得跨次恢复。
7. 配置页面与每日详情修改同一条单日规则时须同步显示，不维护两套相互独立的值。

## 5. 跨功能交互与数据保留

### 5.1 页面安排

- 顶部固定入口进入独立“系统配置”页面，集中管理标准工时、默认上下班、午休、日期段规则与导出目录；返回后保留文件列表、选中日期和未处理事项。
- 导入区域升级为文件清单，明确追加、移除、失败、重复及覆盖区间，不隐藏批量处理状态。
- 每日详情增加“生效作息”“调休扣减模式/数值/原因”“来源文件”，保留原始记录入口。
- 明细筛选增加手动扣减、作息例外、来源冲突和未导入范围；不将其全部混成缺卡。
- 重算之前可查看本次修改影响，保存失败保留草稿；已导出路径始终对应已成功计算的结果。

### 5.2 建议的保存边界

标准工时、默认作息、导出设置和常用日期段规则建议本地持久化，支持恢复默认。员工相关的打卡修订、单日作息和人工扣减建议先维持当前文件集会话内有效，并在导出中留存审计信息。跨次重新打开自动恢复涉及文件内容匹配和员工身份，列为 D03 待确认，不因路径相同直接套用旧修订。

### 5.3 合并、修订与配置的优先关系

先解决来源冲突，再按同一员工和考勤日期应用修订；当日作息决定午休及请假分摊，独立的标准工时 S 参与加班及自动扣减计算，人工扣减覆盖自动 D。追加文件不能重复应用同一日人工扣减。改变作息或标准工时后显示新的自动值，但保留人工最终值并提示其仍被覆盖；恢复自动后才重新采用算法结果。
