## 1. 版本改进方向

本版围绕三个方向整理：修正调休扣减结果、提高日常操作效率、适应制度及发布流程变化。原始建议编号保留为需求编号 R01～R07，方便审阅和追溯。最新回复已将 R03 从福利开关改为永久取消福利，并将考勤日边界改为 04:00；文末原始反馈保持原文。

| 编号 | 类别 | 整理后的需求 | 预期价值 | 建议优先级 |
|---|---|---|---|---|
| R01 | 计算正确性 | 按正常工作时段与请假跨度计算每天申请量，排除实际休息日，并可点击查看原始记录 | 消除误扣并保留追溯依据 | P0 |
| R02 | 操作体验 | 增加时间编辑及重算；导入和编辑统一按当天 04:00 至次日 04:00 前归属 | 修正异常时间并明确跨日边界 | P1 |
| R03 | 规则调整 | 已确认永久取消半小时地点福利，不提供开关 | 避免继续计入已经取消的福利 | P1 |
| R04 | 导入体验 | 支持将单个 .xlsx 文件拖入页面导入区域，保留原有浏览选择入口 | 减少选择文件的操作 | P1 |
| R05 | 计算正确性 | 修正“实际有效工时 4 小时、调休申请 5 小时”场景，净剩加班应为 −4 小时 | 避免超过当天剩余标准工时的调休扣减 | P0 |
| R06 | 未来制度适配 | 支持调整午休时段；当前保留 1.5 小时，未来可设置为 1 小时，标准工时仍为 8 小时 | 降低作息制度调整成本 | P2 |
| R07 | 版本交付 | 完善版本确认后基于 release 分支构建、发布安装包的流程，并排查已有构建失败 | 让正式版本及其安装包可追溯、可复验 | P1 |

P0 表示影响核心计算结果，P1 表示本版主要能力，P2 表示可协商的前瞻能力。该排序用于需求审阅，不代表开发任务顺序或排期。R02 的缺卡补录、R06 的设置入口等属于建议细化，见需求文档的待确认事项。

## 2. 需要明确的业务口径

### 2.1 “请假”与“调休”需区分

当前程序只解析“调休／调休假 N 小时”，并从加班余额中扣减；尚未统一处理年假、事假、病假。本版继续以调休为范围；本轮回复已明确休息日排除，但未单独展开其他假种，不将所有请假直接等同于调休扣减。

### 2.2 跨日问题应依据工作日历判断

已确认休息日不计调休，覆盖普通周六、普通周日和节假日休息日，同时保留国家调休工作日的正常处理。用户示例：周五 09:00 请到周一 18:30，若两端各为 8 小时工作日且中间两天休息，合计请假 16 小时。原回复中的“请假不包含工作日”按该例理解为“休息日不计入”，原文保留在需求文档。

已确认每天的申请量按请假跨度与上午 09:00～12:00、下午 13:30～18:30 的交集计算，午休不计入。页面提供“查看原始记录”入口，展示申请原文、起止时间及来源。工作时段只用于请假分摊，实际工时仍按真实打卡计算。当前代码尚未解析申请起止区间，源表结构及缺少区间时的处理仍需核验，不能将跨日总量每天重复累计。

### 2.3 完整打卡的调休扣减公式已确认

用户已根据补充示例确认：实际有效工作 4 小时、申请调休 5 小时，只扣尚未完成的 4 小时，净剩加班为 −4 小时；如果只申请 2 小时，则只扣 2 小时，净剩加班为 −2 小时。

已确认的公式为：“当日申请量”与“max(8 小时 − 实际有效工时, 0)”两者取较小值。该公式仅适用于工作日打卡完整、实际工时可计算的情形；缺卡以及打卡与申请冲突时如何提示和出结果仍需确认。原始申请 5 小时仍须保留，不改写成 4 小时。地点福利永久取消，不再涉及福利抵扣。

### 2.4 考勤日边界已改为 04:00

一个考勤日覆盖当天 04:00 至次日 04:00 前：次日 03:00、03:59 均归前一天，04:00 归新一天。导入及手动修订统一采用此规则，替代现行 03:00 边界。用户此项回复尚未确认编辑粒度、补卡范围或是否允许把记录挪到其他考勤日。

### 2.5 未来作息尚未生效

本版建议支持配置午休起止时间，默认仍为 12:00～13:30。12:00～13:00 只是未来一小时午休的示例，是否开放配置、具体新时段及生效日期尚未确认；变更午休时必须同步约定对应的请假分摊工作时段。18:00 下班是否达到标准工时还取决于上班时间，不能把固定下班时间直接作为加班判断标准。

### 2.6 当前已具备 GitHub Release 发布能力

现有工作流已支持手动触发或 v* 标签触发，在 Windows EXE 与 macOS DMG 均构建成功后创建 Release。本次应补充 release 分支及正式确认流程，并依据失败日志定位构建问题。创建 release 分支本身不能保证构建成功；历史失败原因目前尚未核实。

## 3. 审阅重点

完整需求、验收场景与待确认项见 [v0.3.0 需求文档](v0.3.0需求文档.md)。建议重点审阅：

1. 跨日申请的报表样式，以及缺少起止区间时如何处理。
2. 缺卡、申请与打卡冲突等不能直接按完整打卡公式处理的情形。
3. 时间编辑粒度、补卡范围、是否跨次打开恢复，及重算后是否继续自动导出。
4. 午休配置是否纳入本版，以及历史报表如何选择适用规则。
5. 正式发布的确认时点、release 分支命名和产物验收方式。

初次整理阶段只处理需求。用户后续已提供真实报表并授权页面规划、测试补充及首轮开发；进展见 [页面规划与迭代计划](v0.3.0页面规划与迭代计划.md) 和 [报表分析与测试用例](v0.3.0报表分析与测试用例.md)。原始反馈及已填写回复继续保留。
