## 1. 背景与目标

用户及同事连续使用后，发现跨日调休和半天调休存在扣减偏差，同时需要修正打卡时间、快速导入文件，并改善正式版本发布流程。第一轮回复已明确永久取消半小时地点福利，并将考勤日边界调整为 04:00。另有午休可能缩短为一小时的消息，目前尚未落地。

本版目标：

1. 调休扣减符合工作日历和每日 8 小时标准，并能解释原始申请与实际扣减之间的差异。
2. 用户可在页面修正参与计算的上下班时间，且明细、汇总和导出结果保持一致。
3. 提供拖放导入，取消半小时地点福利，并统一使用 04:00 考勤日边界。
4. 对未来午休变化提供有限、明确的配置能力，保持现行默认规则。
5. 将正式确认、版本分支、安装包构建和 Release 发布建立为可追溯的交付流程。

## 3. 统一术语与计算原则

### 3.1 术语

| 名称 | 定义 |
|---|---|
| 工作日 | 普通工作日或国家调休工作日，包括被明确安排上班的周六、周日 |
| 休息日 | 普通周末或节假日安排中的休息日，以现有工作日历判定为准 |
| 原始申请记录 | 源表假勤描述、时长、日期及来源信息；保留原值用于追溯 |
| 当日申请量 L | 对申请识别、去重后，根据请假时间跨度与当天正常工作时段的重叠部分计算的调休分钟数；当前时段已在 C11 确认 |
| 实际调休扣减量 D | 经过日期规则和工时限制后，最终从加班中扣除的分钟数 |
| 实际有效工时 E | 打卡跨度扣除适用午休后的时长；缺卡时为未知 |
| 加班 O | 工作日实际有效工时超过 8 小时的部分，休息日为实际跨度；不再加计地点福利，缺卡时保持未计算 |
| 净剩加班 N | 加班减去实际调休扣减，允许为负数 |

本版继续按调休假范围整理，不将年假、事假、病假等自动扣减加班余额。C01 已明确休息日不计请假时长，其他假种的处理未单独展开；若需纳入其他假种须补充相应口径。回复中的“请假不包含工作日”按其后周五至周一合计 16 小时的例子理解为“休息日不计入”，原文及解释保留在第 8 节。普通周末与节假日休息日在文档中分别表述，是否计入均依据工作日历，不能把所有周六、周日一律判为休息。

### 3.2 共通原则

- 以整数分钟计算；小时数只用于显示。工作日标准仍为 480 分钟，休息日为 0。
- 工作日历优先于星期判断。不能用“星期日”直接代替“休息日”。
- 已确认考勤日区间为 [当天 04:00，次日 04:00)：次日 03:59 的打卡仍归前一考勤日，正好 04:00 归新一天。导入打卡和手动修订使用同一边界，替代现行代码的 03:00 规则；请假仍按正常工作时段分摊，不将考勤日整个 24 小时当作可请假时长。
- 已确认永久取消半小时地点福利：地址不再增加实际工时、加班或减少调休扣减，本版不提供恢复福利的开关。
- 已确认当前请假分摊时段为上午 09:00～12:00、下午 13:30～18:30，合计 8 小时。该时段只用于请假分摊；实际工时继续按真实打卡跨度及午休计算，不截断到这两个时段。
- 无调休申请的短工时日期，不因本版改动自动产生“欠工时”扣减。
- 缺卡的实际工时为未知，不得当作 0 代入完整打卡公式。
- 原始文件、原始打卡和原始申请保留；修订值及扣减调整单独展示。
- 计算使用报表中的考勤日期时间语义，不随运行电脑的时区自动改变日期归属。

## 4. 功能需求

### R01：跨日调休按工作日历处理

**原始诉求：** 跨日请假涉及普通周日时，不应额外扣除该休息日的 8 小时。

**已确认方向与分摊建议：** 休息日不计调休；每天请假时长根据当天正常工作时段和请假跨度计算，并提供查看原始记录的入口。

1. 同一申请涉及多个日期时，逐日判断日期类型；休息日 D 为 0，工作日继续执行 R05 的扣减规则。
2. 普通周六、普通周日及节假日休息日均排除；周日若属于国家调休工作日则不能排除。用户已确认：周五 09:00 请到周一 18:30，若周五、周一各为 8 小时工作日且中间两天休息，则合计 16 小时。
3. 按 C02/C11，先识别请假起止时间，再逐日计算与 09:00～12:00、13:30～18:30 两段的交集，排除午休及非工作时段，得到当日申请量 L；一天全部正常工作时段被覆盖时为 8 小时。例如请假 11:00～14:00，L = 上午 1 小时 + 下午 0.5 小时 = 1.5 小时。源表标注的小时数保留用于核对，不把跨日总量在每一天重复累计。是否在缺少区间时接受源表已明确的单日量作为兜底，仍为待确认建议。
4. 同一申请在上下班行或两个工作表重复展示时只计一次；不同的真实申请不得因为描述相同就被跨日期合并。
5. 跨月、跨年及超出统计区间的申请，只计算属于当前区间的部分。区间内每日分配和区间合计必须一致。
6. 无法确定归属日期或当日申请量时（例如只有跨日总量、缺少起止时间），标明具体申请及无法确定的原因；不得简单平均分配、盲目跨日去重或直接假设每天 8 小时。建议暂不输出该申请影响的确定性扣减与总净额，提示“待核对”，可展示其余已确定项目。缺少区间但有明确单日时长的处理须与 C02 的兜底口径一起确认。
7. 每日请假明细提供可点击的“查看原始记录”入口，展示对应申请原文、原始时长、请假起止时间及来源工作表/行号；跨日申请能从任一受影响日期追溯到该申请。入口建议打开应用内详情，不要求改写源文件或外部上传。原始申请中被排除的休息日仍可查看并注明原因。

**样本依据：** 用户已提供三份真实报表。4 月样本中，同一笔 4/24 12:00 至 4/27 13:30 的调休 8 小时申请在四个日期重复出现；按已确认工作时段，当日申请量应为 5、0、0、3 小时，而不是每天 8 小时。本轮据此实现区间识别与去重。未覆盖的字段格式及缺少区间时的处理仍须明确，不以已见样本推定所有供应商格式都相同。

### R02：上下班时间编辑模式

**原始诉求：** 在页面手动修改具体上下班考勤时间。

**建议的首版范围：** 编辑“每日参与计算的上班时间和下班时间”，允许补齐缺失时间；不直接改写源 Excel，也不扩展为逐条原始记录管理。范围待 C05 确认。

用户操作：

1. 计算完成后进入编辑模式，选择某天，查看原始值和当前计算值。
2. 修改上班或下班时间，可累积多天修改；提供“保存并重算”“取消修改”和“恢复当天原始值”。
3. 保存前校验全部修改；成功后统一重算受影响结果，更新明细、汇总、异常状态及导出。取消时保留进入编辑前已生效的结果。
4. 修正后的日期显示“已手动修正”，并能看到原值、修订值和对工时的影响。

时间及数据边界：

- 输入必须能表达实际日期和分钟，支持次日 04:00 前下班，不能只凭一个 HH:mm 猜测跨日。
- 下班必须晚于上班，格式错误或非法日期不可保存。允许只补齐一项；另一项仍缺失时继续保持缺卡。
- 本版建议不支持将打卡挪到其他工作日：输入按已确认的 04:00 规则归属其他日期时，明确提示并拒绝该修订，避免静默更改相邻日期。C05 只确认了日期边界，尚未确认编辑粒度、补卡和跨工作日移动范围。
- 未编辑日期继续按最早上班、最晚下班计算。编辑后的每日覆盖值优先于原首尾值，原始记录仍完整保留。
- 不修改地点；保留地点作为原始信息，按照 R03 不再参与福利计算。
- 恢复原始值后重新按原记录计算；原本缺卡的日期可恢复为缺卡状态。

**存续范围建议：** 修订保留在本次已导入文件的工作会话中，重复计算和规则切换继续使用；更换文件或退出应用后不自动恢复。离开时如有未保存修改，或存在尚未导出的已生效修订，应提示处理。跨次打开恢复属于 C06 的待确认扩展。

### R03：永久取消半小时地点福利

**原始诉求：** 福利可能取消，支持决定是否计入半小时福利。

**最新确认（C04）：** “取消半小时福利，以后不会再有半小时福利”。本项替代原开关方案，不再提供启用、恢复福利的设置。

- 工作日加班只按 max(实际有效工时 − 480 分钟, 0) 计算；任何打卡地点均不增加额外 30 分钟。
- 取消福利不改变实际打卡跨度、午休扣除和 8 小时标准，也不减少调休扣减。
- 页面帮助、计算说明和导出取消福利加计表述。若为兼容原导出格式保留旧福利列，该列应固定为 0 并注明已取消，不作为可选设置。
- v0.3.0 新计算及重新计算统一不计福利，已导出的旧文件保持不变。本版不新增历史福利恢复入口；历史期间若有单独复算旧制度的需求，再另行确认。

例如：工作日实际有效工时为 8 小时，原始地点包含“云岭东路586号”，加班仍为 0；实际有效工时 9 小时，则加班为 1 小时。

### R04：拖放 Excel 导入

**原始诉求：** 可以将 Excel 文件直接拖进页面。

建议将源文件导入区域作为拖放目标，拖入时高亮并显示“松开以选择 .xlsx 文件”。保留“浏览”入口，两种方式共享相同的文件格式与业务校验。

- 一次仅接受一个本地 .xlsx 文件；选择成功显示文件名及路径，再由“开始统计”触发计算。
- 不增加 .xls、多文件批处理或多员工合并能力。扩展名大小写不影响识别。
- 文件夹、多文件、不支持格式、不可读文件和损坏工作簿均有明确错误提示；被拒绝的拖放不清空当前有效结果或修改。
- 正在计算时不替换源文件，提示等待；更换文件时按 R02 处理未保存修改或未导出修订。
- Windows x64 和 macOS arm64 均验证拖放，覆盖中文、空格路径。

### R05：半天调休扣减与净剩加班修正

**已明确的目标示例：** 工作日实际有效工时 4 小时、下午调休申请 5 小时，按 8 小时标准，净剩加班应从 −5 小时修正为 −4 小时。

**已确认的通用规则（C03 后续回复）：** 当天标准 8 小时，先扣掉实际已工作的时长，剩余部分才是最多需要扣的调休；如果实际申请更少，只扣申请的部分。

先看两个示例：

1. **已工作 4 小时，申请调休 5 小时：** 8 − 4 = 还差 4 小时，所以只扣 4 小时，净剩加班为 −4 小时。原始 5 小时和调整原因仍可查看。
2. **已工作 4 小时，只申请调休 2 小时：** 虽然还差 4 小时，但只申请了 2 小时，因此只扣 2 小时，净剩加班为 −2 小时，不补扣未申请的另 2 小时。

两例均已得到用户“同意这条规则”的回复。这里的“已工作”指扣除午休后的实际有效工时；例如 08:00～12:00 打卡可得到 4 小时，下午 13:30～18:30 调休可得到申请量 5 小时。08:00～09:00 虽然早于请假分摊的正常时段，仍计入实际工作。

**对应公式：**

对工作日且打卡完整、时间有效的日期，先按 R01 得到当日申请量 L：

- 标准工时 S = 480 分钟。
- 实际扣减 D = min(L, max(S − E, 0))。
- 加班 O = max(E − S, 0)，不再计入地点福利。
- 净剩加班 N = O − D。

该规则仅限制实际扣减，不将请假时长加入实际工时，也不改写原始申请。先由 R01 按正常工作时段计算 L，再由本项按实际工作缺口限制 D；原始填报量、每日申请量 L 和实际扣减 D 应分别保留。

| 场景 | E | L | D | O | N | 规则状态 |
|---|---|---|---|---|---|---|
| 用户反馈场景 | 4 小时 | 5 小时 | 4 小时 | 0 | −4 小时 | 已确认 |
| 当日申请少于工时缺口 | 4 小时 | 2 小时 | 2 小时 | 0 | −2 小时 | 已确认，不额外补扣未申请的 2 小时 |
| 短工时但无调休申请 | 4 小时 | 0 | 0 | 0 | 0 | 保持原有语义 |
| 原指定地点满勤 | 8 小时 | 0 | 0 | 0 | 0 | 已确认取消福利，地点不影响结果 |
| 实际工作超过标准 | 9 小时 | 0 | 0 | 1 小时 | 1 小时 | 超过 8 小时的部分计加班 |
| 已满 8 小时但仍有调休 | 8 小时 | 2 小时 | 0 | 0 | 0 | 数值按已确认公式；是否允许作为最终结果及冲突提示仍待确认 |

特殊情况：

- 休息日 D = 0；打卡完整时仍将实际跨度计为加班，不扣午休，不加计地点福利。
- 缺卡时不得套用 E = 0。建议保留“可确认的当日调休申请仍扣减”的现有规则，例如工作日全天缺卡、明确单日调休 8 小时，净额为 −8 小时，实际工时仍显示未计算。
- 部分缺卡或时间范围异常时，建议保留已确认的当日申请量扣减并提示无法校验工时上限；跨日总量不明或单日量异常时转为待核对，不输出貌似准确的扣减。这些情形不属于本轮已确认的完整打卡公式，细则仍待 C03 补充确认。
- 手动补卡后重新进入完整打卡公式，扣减随有效工时变化，不能继续使用补卡前的结果。

页面和导出需要区分“原始申请时长”与“实际调休扣减”。例如展示“原始申请 5 小时，本次扣减 4 小时，减少扣减 1 小时：按当天剩余标准工时限制”。汇总的扣减项建议命名为“实际调休扣减”，原始申请在详情保留。

区间净剩加班 = 各日加班合计 − 各日实际扣减合计，并等于各日净额之和。缺卡加班按现有汇总规则以 0 参与合计，但必须保留未计算状态；存在无法确定的扣减时，总净额应标为待核对，不将未知值当 0 后展示为确定结论。

### R06：午休时段配置

**原始诉求：** 未来可能午休一小时、18:00 下班，本版提前考虑调整能力。

**建议的有限范围，待 C08 确认：** 提供工作日午休开始、结束时间设置，默认 12:00～13:30，允许配置为一小时；标准工时保持 8 小时。午休始终按打卡区间与所选午休区间的实际交集扣除。

- 仅支持同一自然日内的单段午休，结束必须晚于开始；不扩展为多班次或夜班排班系统。
- 12:00～13:00 是示例，不能宣称已确定新制度。不会根据运行日期自动改为一小时。
- 示例：09:00～18:00，午休 12:00～13:00，实际有效工时为 8 小时；若仍采用旧午休，则为 7.5 小时。两者均不加计地点福利。
- 午休改变时，请假分摊的正常工作时段也需同步约定。当前已确认的是 09:00～12:00、13:30～18:30；若未来采用 12:00～13:00 午休，建议对应调整为 09:00～12:00、13:00～18:00，以保持每天 8 小时，但该未来方案仍待 C08 确认。不能只改变午休扣除而让请假分摊继续使用不匹配的时段。
- 休息日继续不扣午休。不得把 18:00 设置为固定加班起算点。
- 修改午休规则后标记“规则已变更，待重新统计”，由用户点击重算应用；重算前旧结果明确使用旧规则。结果和导出记录实际使用的午休及请假分摊时段。

**历史期间建议：** 本版每次统计使用一套午休及对应工作时段设置，不按生效日期自动混算。导入历史报表时显示适用范围并要求用户选择对应作息；跨作息制度生效日的报表建议按制度分别导出源报表后统计。若必须在同一报表内自动分段应用规则，需要在 C08 中明确纳入范围。取消福利与 04:00 边界按本版统一规则执行，不作为可选作息配置。

### R07：正式版本构建与 Release 发布

**原始诉求：** 工作流曾多次构建失败；希望每个版本正式确认后创建 release 分支并构建发布对应版本。

**当前事实：** 已有 GitHub Release 自动发布。尚未取得历史失败日志，因此不能认定失败来自 runner、依赖、权限或其他特定原因，也不能承诺创建分支即可消除构建失败。

建议的发布流程（属于产品交付约定，不是本次开发任务拆分）：

1. 版本范围及业务验收确认后，从约定的稳定提交创建版本分支，建议命名 `release/v0.3.0`。
2. 由发布负责人明确触发该分支的候选构建，记录版本与提交；普通开发分支推送不直接生成正式 Release。
3. Windows x64 EXE、macOS arm64 DMG 均构建成功且校验通过，才具备正式发布资格。
4. 建议先提供候选产物或草稿 Release，完成双平台安装、启动、导入和计算检查，再确认发布正式版本。是否采用此第二次确认由 C09 决定。
5. 最终版本标签 `v0.3.0`、Release 和安装包对应同一已验收提交；发布时不混用其他提交的产物。

现有保证继续保留：

- 五处版本号一致：桌面 package.json、tauri.conf.json、Cargo.toml、pyproject.toml、引擎 __init__.py。
- Release 包含 Windows EXE、macOS unsigned DMG、DMG 独立校验文件及统一 SHA256SUMS.txt。
- 任一平台失败时不得宣称正式发布完成；标明失败平台、步骤及日志入口。
- 允许对同一提交重试失败构建；不能让既有版本标签静默指向其他提交。
- 正式发布后的附件建议不再自动覆盖；候选产物可在同一提交下重试替换。现有流程允许同提交覆盖附件，这一收紧规则待 C09 确认。
- macOS 保持当前 unsigned 分发定位，签名、公证及新增平台不作为本版默认范围。

验收构建稳定性时，应以实际失败运行记录为依据说明根因及修复结果，并完成本版双平台验证；不能以“某次恰好成功”替代故障定位。

## 5. 结果、导出与操作一致性

### 5.1 结果解释与追溯

以下信息应能从页面详情及结果 Excel 中追溯，具体列和工作表布局留待设计阶段确定：

| 信息 | 要求 |
|---|---|
| 计算依据 | 软件版本、统计期间、节假日来源、04:00 考勤日边界、午休及请假分摊时段；明确不计地点福利 |
| 原始资料 | 原始打卡、原始申请文本、起止时间、原始时长及来源工作表/行号；每日请假可点击查看对应原记录 |
| 时间修订 | 原时间、修订时间、是否手动修改；补录值与原始值可区分 |
| 调休处理 | 当日申请量、实际扣减量、排除或限制原因；未知分配明确标记 |
| 汇总结果 | 日明细、汇总卡片、详情、净额余额及 Excel 使用同一结果 |

保留现有四类导出信息：月度汇总、每日明细、原始打卡记录、原始调休记录。可补充修订及规则说明，但不得把修订后的记录伪装成原始记录，也不得把跨日重复显示的总量再次累计为原始申请合计。

### 5.2 重算与导出行为

当前应用计算时自动导出。草案建议继续此行为：时间修改集中保存后、规则修改后点击重算时，生成与新结果一致的 Excel；不在每次输入字符时导出。是否改为单独“导出”按钮由 C07 确认。

- 重新计算中保留上一份成功结果，并明确标记处理中；计算及导出均成功后统一替换，避免局部显示新旧两套数值。
- 计算或导出任一失败时，保留待应用的修改和上一份成功结果，提供失败原因及重试方式，不能误报保存或导出成功。首次统计失败时不展示成功结果。
- 计算成功但导出失败时，建议仍不将新结果应用到页面，待重试成功后统一更新；旧输出路径明确属于上一份结果，不能标成当前修改的导出。
- 重复导出保留原有文件，不静默覆盖源报表或历史结果。
- 编辑中的草稿未处理前，不同时应用规则切换；先保存或取消编辑，再统一重算。

### 5.3 配置范围建议

午休及对应工作时段配置作用于本次整个统计期间。建议首次使用当前作息：午休 12:00～13:30，请假分摊时段 09:00～12:00、13:30～18:30；用户调整后可记住最近选择，后续导入时清楚显示，不能暗中重写已有结果。每份导出固化当次规则。是否开放配置、记忆设置及按日期自动切换，仍见 C08；取消福利及 04:00 边界已确认，不提供旧福利开关。

## 6. 非功能要求与兼容边界

1. 保持个人考勤数据本地处理；原始 Excel 不被就地修改。
2. v0.3.0 复算历史报表时，调休修正、取消地点福利及 03:00 改为 04:00 边界均可能改变结果，必须说明差异原因；未涉及这些变化且使用相同午休设置的数据应保持一致。已导出的历史文件不被改写。
3. 保留完整日期骨架、国家调休日历优先级和缺卡状态语义；导入、编辑及详情展示均使用 04:00 打卡归属边界。
4. 未知节假日安排沿用现有安全失败行为，不为完成统计而猜测；计算错误应定位到具体日期或来源信息。
5. 时间编辑、拖放、取消福利、04:00 归属及导出须在 Windows x64、macOS arm64 验证，不以浏览器页面演示替代桌面验收。
6. 保存与重算期间有明确状态，避免重复提交；规则在前端展示和实际计算中的含义一致。
7. 内置帮助、计算说明及相关文案同步采用新口径，尤其区分原始调休与实际扣减。
