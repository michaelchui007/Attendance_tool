## 1. 产品参考与取舍

本次查看产品官方文档，关注工时核对的实际操作，不直接照搬品牌视觉或多人管理功能。以下是页面规划依据，不代表本工具已经具备参考产品的全部能力。

| 参考 | 官方页面中可观察到的能力 | 本项目采用的思路 |
|---|---|---|
| Clockify Detailed report | 明细列表、筛选、直接编辑起止时间、跨夜条目日期提示、导出 | 让每日明细承担主要核对工作，编辑靠近具体日期，跨日时间明确标注，导出对应当前结果 |
| Harvest Time tracking | 简洁的按日/按周工时记录、工时总览和修改追溯 | 减少首页装饰，先展示重要结果，再下钻到时间和来源；保留原始值与修订值 |

官方参考（查阅日期 2026-11-06）：

- Clockify：`https://clockify.me/help/reports/detailed-report`
- Harvest：`https://www.getharvest.com/features/time-tracking`

本工具用于单人本地考勤，不增加组织架构、审批导航、项目计费或多人权限菜单。页面重点是解释“净剩多少、为什么、哪些日期需要修正”。

## 2. 页面信息结构

从上到下分为四个区域：

1. **紧凑顶栏**：产品名称、当前版本、本地处理提示、帮助入口。标题不占据大面积首屏。
2. **导入与操作区**：拖入/浏览单个 .xlsx、显示当前源文件和输出位置、展开计算规则、开始统计或重新统计。已有结果时明确源文件和统计期间。
3. **汇总区**：净剩加班作为主要指标；加班、实际调休扣减和需核对日期作为辅助指标；应计标准和实际有效工时放在次级信息行。
4. **每日工作区**：左侧明细表，右侧选中日期详情。用户筛选、查看原因和修正时间时保持日期上下文。窄窗口改为上下排列。

### 2.1 主次关系

- 净剩加班不与所有统计数字等权展示；负数保留负号，不以颜色代替数值。
- “未计算”“待核对”和正常 0 小时必须不同。缺卡和申请区间无法识别分别说明。
- 不新增缺乏业务用途的趋势图、排行榜或图表；该工具最重要的比较是某一天的原始申请、当日量和实际扣减。
- 有异常时提供快捷筛选；不能把普通休息日无打卡的提示和待核对申请混成一个无法解释的数量。

### 2.2 每日明细

建议展示日期/星期、日期类型、上下班、实际有效工时、实际调休扣减、净剩加班和状态。保留按全部、异常、调休、已修订等条件筛选的能力，具体筛选项以实际实现为准。

表头固定，数字使用等宽数字并右对齐，所选行有清晰背景。日期类型、缺卡、待核对和手动修订分别表达。选择一行后右侧同步展示该日详情，不跳到无关页面。

### 2.3 日期详情与来源

详情依次呈现：

1. 日期、日期类型和当前状态。
2. 本次计算的上班/下班时间，跨日下班显示实际日期或“次日”。
3. 实际工时、午休、当日调休申请量、实际扣减及净额。
4. 计算说明，例如“申请 5 小时，按剩余标准工时扣减 3 小时 52 分钟”。
5. “查看原始记录”：对应申请原文、起止时间、源工作表/行号，以及原始打卡。
6. 修改时间、保存并重算、取消、恢复原始值。修订与源记录分开展示。

原始信息仅在本地详情中展示，不发送到外部产品或研究网站。

## 3. 视觉与交互规范

| 项目 | 方向 |
|---|---|
| 背景 | 浅灰蓝工作区、白色内容面板 |
| 主色 | 深蓝用于主操作，青绿色只作少量强调 |
| 状态色 | 正常中性、需核对暖色、操作错误红色；同时提供文字 |
| 间距 | 以 8 像素为节奏，表格保持适当密度 |
| 面板 | 轻边框和克制阴影，统一圆角，不使用大面积装饰渐变 |
| 文字 | 沿用项目字体，标题/正文/辅助信息层级明确，数字使用等宽数字 |
| 主操作 | 每个状态有清晰主要动作，计算中禁用重复提交并显示进度状态 |
| 键盘 | 表格行可键盘选择，表单控件有标签和焦点，抽屉可关闭 |
| 窄窗口 | 明细与详情上下排布，不截断关键按钮或使整页横向溢出 |

### 3.1 状态流转

- 空状态：显示拖放入口、支持的报表格式及浏览按钮。
- 已选文件：显示路径，用户点击开始统计，不因拖放立刻重复计算。
- 计算中：保留已有结果并说明正在处理的文件，禁止重复启动。
- 成功：更新整个结果和相应导出路径。
- 有修订：保留原始值，集中保存后重算；失败时不丢修改。
- 规则变更：显示待重算提示，旧结果仍注明旧规则。
- 失败：显示可操作的原因，保留上一份成功结果，不将旧导出冒充新结果。

## 4. 首轮实现范围与默认选择

用户已授权开始迭代。已确认业务规则直接实现；未单独答复的交互细节采用可调整的首轮选择，不写成用户已确认的最终制度。

| 范围 | 首轮处理 |
|---|---|
| 调休计算 | 跨日申请按工作时段分摊、休息日排除、重复申请去重、完整打卡按工时缺口限制扣减 |
| 福利与边界 | 永久取消福利，导入和修订统一 04:00 考勤日边界 |
| 原始追溯 | 保存申请来源及原文，页面可查看，导出保留依据 |
| 时间编辑 | 每日首尾覆盖、可补卡、可恢复；只在当前文件会话保留，不修改源文件 |
| 导出 | 延续计算成功自动导出的现有行为，集中保存后生成新结果，防止覆盖同名历史文件 |
| 午休适配 | 默认旧作息；提供手动调整能力，正常工作时段保持每天 8 小时；不自动宣称新制度已生效 |
| 缺卡 | 不把未知工时当 0；可确认申请沿用扣减并明确状态，无法分配的申请标待核对 |
| 发布 | 本轮不发布安装包，不创建 release 分支；已有失败日志与正式确认细节另行落实 |
